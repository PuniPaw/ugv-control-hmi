# ADR-002. 바이너리 메시지는 big-endian 정수 고정소수점으로, 필드별 명시 직렬화한다

| 항목 | 내용 |
|---|---|
| 상태 | 승인 |
| 날짜 | 2026-11-10 |
| 관련 | UGVC-ICD-001 3장·4장·6장, REQ-COM-001, REQ-COM-002, REQ-QUAL-001 |

## 배경

- 송신 측(SIM, DET)은 Python, 수신 측(GW)은 C++이다. 언어와 플랫폼이 달라도 바이트 단위로 같은 해석이 보장되어야 한다.
- C/C++ 구조체를 그대로 `memcpy`하면 컴파일러의 패딩·정렬과 CPU의 엔디언에 따라 결과가 달라진다.
- 부동소수점은 플랫폼 간 표현 차이, NaN/Inf 처리, 비교 연산의 모호함 때문에 검증 규칙(범위 검사)을 정의하기 까다롭다.
- 방산 데이터링크 규격은 일반적으로 정수 필드에 LSB(최소 단위)를 정의하는 방식을 쓴다.

## 선택지

| 항목 | 선택지 | 판단 |
|---|---|---|
| 바이트 순서 | little-endian (x86 기본) / **big-endian (네트워크 바이트 순서)** | 네트워크 프로토콜 관례를 따르고, 패킷 덤프를 사람이 읽기 쉽다 |
| 수치 표현 | float/double / **정수 + LSB 명시** | 범위 검사를 정수로 정확히 정의할 수 있고 NaN이 존재하지 않는다 |
| 직렬화 방식 | 구조체 memcpy / Protobuf 등 IDL / **필드별 명시 직렬화** | 패딩·엔디언 문제가 없고, 외부 의존 없이 ICD 표와 코드가 1:1로 대응한다 |

## 결정

- 모든 다바이트 필드는 **big-endian**으로 송신한다.
- 실수 값은 **정수형 고정소수점**으로 표현하고, ICD에 필드별 LSB와 범위를 명시한다.
  - 예: 위도 `i32`, LSB 1e-7 deg (약 1.1cm 분해능), 속도 `u16`, LSB 0.01 m/s
- 직렬화는 **필드별로 명시적으로** 수행한다. C++은 `write_u16_be()` 같은 헬퍼, Python은 `struct.pack(">...")`를 쓴다. 구조체 `memcpy`와 `#pragma pack`은 금지한다.
- 공학 단위(deg, m/s) 변환은 GW에서 HMI로 보낼 때(IF-03 JSON)만 수행한다.

## 결과

- 직렬화·역직렬화 함수는 순수 함수가 되어 GoogleTest로 바이트 단위 검증이 쉽다 (REQ-QUAL-001). 같은 테스트 벡터를 Python 쪽에도 적용해 양쪽 구현의 일치를 확인한다.
- ICD 범위 검사(9장 8번)를 정수 비교로 정확히 구현할 수 있다.
- 필드 추가 시 ICD 표, C++ 코드, Python 코드를 함께 수정해야 하는 부담이 있다. 메시지 수가 적은 현 단계에서는 감수하고, 메시지가 늘어나면 ICD에서 코드를 생성하는 방식을 검토한다.

## 면접 대비 한 줄

> "Python과 C++ 사이에서 패딩·엔디언 차이를 없애려고 구조체를 그대로 보내지 않고 필드별로 big-endian 직렬화했고, 실수는 LSB를 정한 정수로 보내서 범위 검증을 정확하게 만들었습니다."
