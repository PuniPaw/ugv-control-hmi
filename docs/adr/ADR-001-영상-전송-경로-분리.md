# ADR-001. 영상 전송 경로를 제어 링크와 분리한다

| 항목 | 내용 |
|---|---|
| 상태 | 승인 |
| 날짜 | 2026-11-10 |
| 관련 | UGVC-ICD-001 IF-04, REQ-AI-001, REQ-AI-002, REQ-LOG-002 |

## 배경

- 640 × 480 JPEG 한 장은 수십 KB로, ICD의 최대 패킷 크기(1200 바이트)를 크게 넘는다.
- 영상을 UDP 바이너리로 게이트웨이를 거쳐 보내려면 분할, 재조립, 일부 조각 유실 시 프레임 폐기 로직이 필요하다.
- 게이트웨이의 핵심 목적은 텔레메트리·탐지·명령 같은 작은 제어·상태 메시지의 신뢰성 있는 처리이며, 포트폴리오에서 보여 주려는 것도 이 부분이다.
- 탐지 박스를 정확한 프레임에 그리려면 영상과 탐지 결과를 연결할 키가 필요하다.

## 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. UDP 분할 전송, 게이트웨이 경유 | 경로가 하나라 구성이 단순해 보임 | 재조립 구현 부담이 크고, 게이트웨이 부하와 지연이 증가함 |
| B. RTSP / WebRTC | 실제 영상 스트리밍 표준 | 프레임 단위 메타데이터(frame_id) 전달이 번거롭고 설정이 복잡함 |
| C. DET → HMI WebSocket 바이너리 직송, 앞에 frame_id·capture_ts 12바이트 헤더 | 구현이 간단하고, frame_id로 탐지와 정확히 동기화됨 | 게이트웨이 로깅에서 영상이 빠짐 |

## 결정

**C를 채택한다.** 영상은 DET에서 HMI로 직접 보내고, 탐지 결과만 UDP로 게이트웨이를 거친다. HMI는 frame_id가 같은 프레임과 탐지 결과만 겹쳐 그린다.

## 결과

- 게이트웨이는 작은 고정 형식 메시지 처리에 집중할 수 있다.
- 제어 링크와 영상 링크가 분리되어, 한쪽이 끊겨도 다른 쪽은 계속 동작한다. 실제 무인체계에서도 흔히 쓰이는 분리 구성이라는 점을 설명할 수 있다.
- 사후 재생(REQ-LOG-002)에서 영상은 제외한다. 필요하면 고도화 단계에서 DET가 프레임을 파일로 저장하는 방식을 검토한다.
- 탐지 결과가 늦게 오는 경우를 대비해 REQ-AI-002(0.5초 타임아웃 후 박스 없이 표시)를 둔다.

## 면접 대비 한 줄

> "영상은 크기가 커서 UDP 단편 재조립 부담이 있고, 관제 게이트웨이의 목적은 제어 메시지의 신뢰성이라서 영상 링크를 분리했습니다. 대신 frame_id로 탐지 결과와 프레임을 정확히 맞췄습니다."
